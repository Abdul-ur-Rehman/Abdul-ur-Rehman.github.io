§ 01

Professional summary

Who I am, how I work and what I bring to an engineering team.

An SDET who treats testing as an engineering discipline — building the frameworks, data, pipelines and tooling that turn a test suite into a signal teams can trust.

Over five years I've moved across the stack of quality: from backend data validation on change-data-capture engines spanning SQL Server, MySQL and Oracle, to building UI and API automation frameworks from the ground up in Playwright, Selenium and REST Assured — in TypeScript, Java and Python.

Today I own a 5,000+ case regression suite across six business verticals at Dubizzle Labs. My work sits where test design meets infrastructure: parallel execution and sharding, API-driven test data, resilient authentication, thread-safe configuration, and CI on GitHub Actions, Jenkins and Azure DevOps.

I care about speed as much as coverage. I've cut regression CI time by nearly half by replacing UI setup with API seeding, taken a reporting job from 50 minutes to under two through SQL and index design, and helped bring a 45-minute build pipeline down to 15.

I'm increasingly focused on AI-assisted quality engineering — agents that triage failures, generate tests and review pull requests, always gated by deterministic checks — and on testing LLM-powered systems themselves. I also mentor engineers on automation and test design to push quality left.

§ 06

Principles

i.

Fix flaky tests, or delete them.

A retried failure is a hidden bug — in the product or in the test.

ii.

A failure should explain itself.

A precise failure message is worth more than clever test code.

iii.

Quality is owned, not handed off.

Developers own their tests; QA builds the system that makes that easy.
